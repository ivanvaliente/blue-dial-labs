Working product name · In development

WristAtlas gives watch software a canonical identity layer.

Watch data arrives with inconsistent names, reference formatting, aliases, variants, and source-specific identifiers. WristAtlas is Blue Dial Labs' canonical watch identity product for resolving that evidence to stable canonical watch identities with provenance and confidence.

Primary question

What watch is this—and how confidently can the evidence be mapped to a canonical identity?

Canonical data model

A stable hierarchy for identifying the product.

The canonical model separates a brand, collection, model, reference, and variant so downstream applications do not need to reinvent watch identity as free text.

  1. 01
    Brand

    The manufacturer or marque.

  2. 02
    Collection / Family

    The product family used to organize related models.

  3. 03
    Watch Model

    The model-level identity shared by references where appropriate.

  4. 04
    Reference

    The core canonical reference identity used across market evidence.

  5. 05
    Variant

    A materially distinct configuration below the reference when needed.

Product overview

Identity, resolution, provenance, and confidence.

Canonical lookup

Resolve a watch to a stable identity.

Exact reference lookup, normalized reference forms, aliases, and structured attributes can converge on Blue Dial Labs-controlled canonical identifiers.

Variant resolution

Do not flatten meaningful differences.

Dial, material, configuration, generation, and other supported distinctions can remain explicit when they materially affect identity or comparison.

Provenance

Preserve where an assertion came from.

Canonical data should distinguish source evidence from normalized interpretation rather than losing lineage during ingestion.

Confidence

Uncertainty stays visible.

Low-confidence matches should remain candidates for review rather than silently becoming authoritative reference assignments.

Data / API concept

Built first as infrastructure WristOwl already needs.

WristAtlas may later support external search, lookup, identity-resolution, catalog-reconciliation, or data-feed use cases. Those are product hypotheses, not announcements of a public production API.

01 / Internal first

Prove the identity layer inside Blue Dial Labs.

WristOwl needs canonical identity for Pursuits, offer matching, market observations, ownership continuity, and confidence-aware recommendations.

02 / Reusable boundary

Keep the capability product-neutral.

Stable identifiers and explicit contracts should make later reuse possible without creating a second competing identity namespace.

03 / External later

Commercialize only after validation.

Public API access, authentication, quotas, coverage guarantees, pricing, SLAs, and external customer workflows remain unannounced.

Relationship to WristOwl

WristAtlas identifies. WristOwl decides.

WristAtlas should not contain collector-specific rankings or recommendations. WristOwl should consume canonical identity rather than inventing a separate reference universe.
